# 📋 個人拜訪紀錄系統 (Visit Tracker)

這是一個專為個人設計的輕量級拜訪紀錄與管理系統。本專案旨在協助使用者記錄大量的拜訪對象資料（如姓名、性別、地址、對話內容、拜訪日期等），並能有效排定下一次的拜訪時間與進行資料篩選。

專案歷經了從 **v1.0 基礎版** 到 **v2.0 輕量級 CRM 系統** 的探索與開發，目前網頁已成功部署至 GitHub Pages。

---

## 🚀 專案發展歷程與目前進度

### 🔹 v1.0 基礎版（已完成）
* **核心功能**：實現拜訪對象的基本資料新增、讀取與呈現。
* **資料儲存**：使用瀏覽器內建的 `localStorage` 進行資料讀取與保存。
* **介面設計**：基本的 HTML 表單與資料列表。
* **網站部署**：成功將專案上傳至 GitHub，並透過 **GitHub Pages** 部署為線上靜態網站。
* **測試數據**：透過瀏覽器主控台（Console）執行種子資料小程式，成功在線上版灌入初始資料。

### 🔸 v2.0 輕量級 CRM 進階版（架構規劃與部分實作）
為了讓專案更實用，我們規劃並嘗試了以下進階架構：
1.  **資料儲存升級**：規劃採用 Google Sheets（雙工作表：`visitors` 與 `visit_logs`）搭配 Google Apps Script (GAS) 作為後端 API，並加入 `owner` 標籤以支援多人獨立管理。
2.  **前端多頁面架構 (SPA)**：採用前端單頁式應用機制，規劃三大核心區塊：
    * **儀表板 (Dashboard)**：一進入網站即可看到資料統計（如總對象數、各階段狀態人數）。
    * **拜訪總表**：可按不同條件篩選資料的總表頁面，全面改用 **卡片式 RWD 響應式設計**。
    * **詳細追蹤紀錄**：點擊卡片後，能切換到該對象的時間軸（Timeline）歷史紀錄頁面。
3.  **核心資料流串接**：
    * 實作系統設定頁面，將 GAS 網址與代號儲存於 LocalStorage。
    * 利用 `fetch(doGet)` 讀取試算表資料倒回前端資料庫（`dbData`）。
    * 規劃透過 `POST` 將新對象與歷史紀錄回寫至 Google Sheets。

## ⚠️ 專案目前狀態與開發心得

本專案目前進行到 v2.0 的資料串接與多頁面切換階段，並已將現階段程式碼部署上線。經過評估後，決定將專案暫時停下：

* **程式碼複雜度超出預期**：在不使用後端網頁伺服器（如 Node.js/Python）與前端框架（如 React/Vue）的情況下，純粹使用**靜態網頁（Vanilla JS）**去模擬動態網頁的行為（如單頁路由 SPA、動態綁定 ID、複雜的時間軸渲染、處理異步 fetch API 與 GAS 的跨網域通訊），導致程式碼的邏輯與架構變得極為複雜，目前身為程式初學者較難完全掌握。
* **功能未達預期效果**：部分前端與 Google Sheets 試算表同步回寫、動態詳情頁綁定的功能，在實際測試時無法達到預期的流暢與穩定效果。
